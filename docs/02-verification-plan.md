# 阶段 4 · 独立验证计划（组长编制，交独立验证员执行）

> 编制依据：`docs/00-G0-scope.md`（验收标准）、`docs/01-recon-findings.md`（行为规格）、`recon/evidence-pack.md`（证据包 A–I）。
> 目的：让验证员**独立证明复刻品可用**，而不是确认文件存在。验证员不得修改实现代码，只出具差异报告。

## 1. 比对条件（先对齐，条件不对齐不比对）

| 项 | 设定 |
|---|---|
| 复刻品入口 | `site/index.html`（`file://` 直开）或本地 http server 根 |
| 参考品 | `https://usersearch.ai/m/search` —— **登录墙 + Cloudflare 403，合规范围内不可观察** |
| 视口 | 移动端 390×844 与桌面 1440×900 各一轮；设备像素比 1 |
| 数据状态 | 全量占位/合成数据；初始额度、Case、历史按产品默认值 |
| 登录态 | 复刻品使用本地演示会话；参考品无会话（且禁止获取） |
| 时序 | 等页面完全加载后再执行操作序列；每个异步状态等待其稳定或超时 |
| 采集时间 | 2026-11-06，验证时如实填写 |

## 2. 四轴可比性裁决（必须写进差异报告）

| 轴 | 可比性 | 原因 |
|---|---|---|
| 视觉（同尺寸同状态截图比对） | **不可比** | 目标页受登录墙保护，且用户明确禁止绕过；无参考截图。改做「复刻品自身在两种视口下的布局/可读性检查 + 与公开文档描述的结构对照」，不得声称像素一致 |
| 交互（同序列操作 → 结果） | **部分可比** | 参考品侧只有公开文档描述的行为规格（P01–P14），无实测操作序列。改做「复刻品操作序列 → 是否与证据包的交互规格一致」 |
| 网络（请求序列/方法/状态/载荷） | **不可比** | 证据包 §C.4 / §E.4 为空表，0 条请求捕获；且复刻品为纯前端占位数据，本就不发真实检索请求。明确标注，不硬凑结论 |
| IPC | 不适用 | 非 Electron 目标 |

> 验证员必须把「不可比」单独成节并写明原因，不得把不可比项降级成「一致」或「差异」。

### 3.4 边界输入矩阵

空字符串、纯空格、前后带空格、含完整 URL、超长（>256 字符）、特殊字符（`< > ' " & / \`）、中文/emoji、邮箱格式、手机号格式、域名格式、批量 1/5/6 条、余额正好等于成本、余额差 0.01、数据源全关、过滤器全收紧、翻页到末页。

## 4. 运行证据要求

- 复刻品自测：`node site/tests/selftest.mjs` 的实际输出（通过/失败数）必须记录；验证员**自行重跑一次**，不能只信实现工程师的记录。
- HTTP 可达性：本地起服务后 `index.html / styles.css / data.js / core.js / app.js` 均 200 且非空。
- 浏览器：可用 Edge headless `--screenshot` / `--dump-dom` 取证；无头截图若中文缺字如实记录。
- 每条差异必须含：**现象 + 复现步骤 + 证据 + 期望 vs 实际 + 级别**。

## 5. 分级与复验

| 级别 | 判定 |
|---|---|
| 阻断 | 核心流程不可用、状态缺失或行为相反、数据/成本算错、file:// 打不开、导出或自测失败 |
| 重要 | 次要功能偏差、明显布局错位、错误处理缺失、状态不可复现、对比度不达标 |
| 次要 | 文案措辞、细微样式、非关键排序 |

- 修复由实现工程师执行；**必须由提出该差异的同一位验证员复验**，给出「已消除 / 未消除 / 部分消除」。
- 存在未解决阻断级差异时，组长不得给出可交付判断。

## 6. 合规复核（验证员也要查）

- 全站不得出现原站品牌名、Logo、模块名、第三方数据源名、真实价格、受保护文案与截图。
- 不得有指向原站域名的请求；不得有真实个人信息；不得有登录/鉴权绕过逻辑。
- 所有结果为合成占位数据。
