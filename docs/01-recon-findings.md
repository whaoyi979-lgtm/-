## 0. 最重要的一条结论（请先读）

**目标页本身无法在合规范围内直接观察。**

| 证据 | 实测结果 |
|---|---|
| X3-1 · `WebFetch https://usersearch.ai/m/search` | 返回的是**登录页**：`Login \| UserSearch 2.0`、`Enter your credentials to continue`、Email / Password / 记住登录 / 登录按钮 / 邮件登录链接 / 第三方登录 / 注册入口 / 忘记密码入口。即 `/m/search` 位于**登录墙之后**。 |
| X3-2 · `curl -sS -L https://usersearch.ai/m/search` | HTTP **403**，正文为 Cloudflare `Just a moment...` 质询页。 |
| X3-3 · `WebFetch https://usersearch.ai/`、`/m/auth/register` | 均只返回 `Just a moment...`。 |

因此：**目标页的 DOM 层次、前端 bundle、路由、接口路径、请求/响应结构，本次一手证据为 0**。任何声称"侦察到了目标页接口"的说法都是不成立的。按合规要求，遇到登录墙与 403 即停止，不做绕过。

但同品牌（不同域名）的**官方公开文档页**无需登录即可直读，且对搜索流程、输入项、结果字段、状态文案、边界处置有逐字级描述。这些构成可复核的一手公开证据，足以支撑一次**行为对齐的功能复刻**。本次因此采用「公开文档驱动的行为复刻 + 全量占位数据」路线。

## 2. 搜索流程

【B·公开文档，X1】官方把流程定义为固定的五步，且强调"consistent flow"：

```
① 选择搜索类型  →  ② 选择模块  →  ③ 按需配置（数据源/过滤器）
        →  ④ 输入查询并确认成本  →  ⑤ 执行并复核结果
```

| 步 | 行为 | 关键约束（原文要点） |
|---|---|---|
| ① | 选顶层搜索类型，决定"查什么" | 公开文档列出 **18 类**：用户名/邮箱/电话/人物/企业/网络空间/IP/产品/聊天/论坛/图片/加密资产/车辆/威胁情报/无线设备/域名/泄露暴露/法庭记录 |
| ② | 选一个模块（具体检索工具） | 模块决定**输入项、数据源、单次成本**；选中态有高亮边框 |
| ③ | 可选配置 | 齿轮控件展开站点过滤或"选择数据源"窗口；多源扫描（OneScan）可对**一个输入**勾选多个来源 |
| ④ | 输入查询并看成本 | 查询按钮上方有"单次成本"行；成本分 **免费 / 固定 / 浮动** 三类；浮动成本随所选来源实时求和 |
| ⑤ | 执行并复核 | 结果需看来源归因并二次佐证；第三方置信度只是信号，不等于身份确认 |

**两个可叠加的批量维度**【B】：
- 多源扫描：1 个输入 × N 个数据源，结果合并并保留来源归因，成本 = 所选来源之和。
- 批量查询：N 个输入（**上限 5**）× 1 个模块，每条算一次查询，成本累加。两者可同时使用，总成本 = 输入数 × 所选来源成本之和。

**留存行为**【B】：保留模式把搜索历史写入所选 Case；隐私模式不写历史。结果可加书签、生成报告、导出 XLSX。

## 3. 输入项清单

| # | 输入项 | 控件 / 约束 | 证据 |
|---|---|---|---|
| 1 | 搜索类型 | 18 类单选导航，决定后续模块集合 | B · X1 |
| 2 | 模块 | 单选卡片，选中高亮；未选模块时点查询不会填充结果 | B · X2「A search seems stuck」 |
| 3 | 查询值 | 文本框，字段名随模块变化（如某模块为 `Username`，另一模块为 `Search query`）；要求**与模块匹配** | B · X2「Check the input」 |

| 6 | 过滤器 | 扫描上限（默认 Top 500）、检索类型（默认 Any）、站点地区（默认 Any）；`重置` / `应用筛选` | B · X2 |
| 7 | 实体类型页签 | 泄露暴露类搜索有实体类型条（全部/邮箱/电话/IP/CIDR/MAC/域名/URL/比特币/IBAN 等） | B · X2 |
| 8 | 批量输入 | 工作台表头的开关，最多 5 条 | B · X2 FAQ |
| 9 | 搜索模式与 Case | 保留/隐私模式、Case 选择 | B · X1 |
| 10 | 充值 | 预设金额、自定义滑块（10–200）、单次或周期、结算按钮 | B · X2 |

### 输入校验与边界（文档明确点名的坑）【B·X2】

- 输入与模块字段要匹配；**多余空格要清除**；需要裸用户名/邮箱时**不要传完整 URL**。
- 搜索类型选错（例如用只收用户名的类型去查邮箱/电话）会导致零命中——这是**输入问题，不是系统故障**。
- 过滤器过窄（扫描上限、指定国家）会显著缩小扫描范围，导致零命中。
- 空查询 / 未选模块 / 未点主按钮 → 结果面板保持初始空态，不会发起检索。
- 批量输入超过 5 条应被阻止。
- 单次成本高于余额时，不允许执行。

## 6. 网络与前端技术特征

【A·实测】仅能确认：`usersearch.ai` 前有 Cloudflare 质询层（403 + `Just a moment...` + 指向 `challenges.cloudflare.com` 的 CSP）；`/m/` 路径下存在登录、注册、重置密码等路由；登录页引用了 `https://usersearch.ai/assets/images/icons/google.png` 这一静态资源路径。

**以下内容本次不可得，且没有尝试获取**：SPA 框架与版本、bundle/chunk 清单、source map、API 基址与路径、请求方法/参数位置/响应结构、鉴权方式（Cookie / Token / 会话）、错误码体系、真实接口流量。原因：均需登录态或需绕过访问限制，超出用户给定的合规边界。对应 `spa-contract-rebuild` 的 `unpack_spa.js` / `probe_contract.js` / `ab_probe.js` / `login_diag.js` 因此**均未对目标站运行**（脚本存在且已核对，Node v22.22.2 可用）。

> 这一点必须写进交付遗留项：本复刻对齐的是**公开文档描述的行为**，不是抓包得到的接口契约。
